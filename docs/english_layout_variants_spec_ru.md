# Спецификация: поддержка вариантов английской раскладки

## Problem Statement

Stepler сейчас распознаёт английскую раскладку только по идентификатору
`en-US` (`0x0409`). После установки английской раскладки UK (`en-GB`,
`0x0809`) Windows продолжает показывать и использовать обе раскладки, но
Stepler не находит английскую целевую раскладку. В результате нажатие Ctrl и
другие операции, которым нужно переключить систему на английский, доходят до
обработчика, но завершаются `Unsupported`.

## Solution

Stepler должен находить установленную английскую раскладку по семейству
`en-*`, а не только по варианту `en-US`. Для текущей машины раскладка
`en-GB` должна считаться валидной английской целью. Найденная раскладка должна
одинаково использоваться обычным layout switcher и терминальным clipboard
fallback.

## User Stories

1. Как пользователь с английской раскладкой US, я хочу, чтобы P/CP и Ctrl
   продолжили переключать систему на английский, чтобы обновление resolver не
   изменило существующее поведение.
2. Как пользователь с английской раскладкой UK, я хочу, чтобы P/CP и Ctrl
   переключали систему на `en-GB`, чтобы мне не требовалась раскладка US.
3. Как пользователь с другим вариантом `en-*`, я хочу, чтобы Stepler
   использовал установленный английский вариант, чтобы поддерживались локальные
   варианты английского без отдельного патча под каждый код.
4. Как пользователь с русской и английской раскладками, я хочу, чтобы выбор
   английской цели не путался с русской раскладкой, чтобы направление
   переключения оставалось однозначным.
5. Как пользователь с несколькими установленными английскими вариантами, я
   хочу, чтобы выбор был детерминированным и следовал порядку, который сообщает
   Windows, чтобы результат не менялся между повторными операциями.
6. Как пользователь терминала, я хочу, чтобы clipboard fallback использовал
   тот же найденный вариант `en-*`, что и обычное переключение, чтобы P/CP не
   расходились по поведению между приложениями.
7. Как пользователь без установленной английской раскладки, я хочу получить
   явный безопасный `Unsupported`, а не случайное переключение на другую
   раскладку.

## Implementation Decisions

- Ввести отдельное понятие английского primary language ID и сопоставлять с ним
  варианты `en-*` через primary language bits Windows LANGID.
- Для английского выбирать первый подходящий HKL в стабильном порядке,
  возвращённом Windows. Не добавлять автоматическую установку раскладки и не
  менять порядок пользовательских раскладок.
- Сохранить точное сопоставление для русского языка и остальных направлений.
- Использовать общий helper для layout switcher и terminal clipboard fallback,
  чтобы они не имели разных правил выбора английской цели.
- При отсутствии `en-*` сохранять fail-closed результат `Unsupported`.

## Testing Decisions

- Тестировать внешний контракт выбора layout ID через чистые unit-тесты
  resolver-а: `en-US` (`0x0409`) и `en-GB` (`0x0809`) распознаются, русский
  (`0x0419`) не распознаётся как английский.
- Проверить несколько вариантов `en-*` и отсутствие подходящего варианта.
- Проверить, что при нескольких английских HKL выбирается первый в переданном
  порядке и результат детерминирован.
- Выполнить существующий набор Rust-тестов платформенного crate.
- После сборки выполнить ручной smoke на локальном PowerShell с `en-GB`, а
  также P/CP и Ctrl в обычном приложении и терминальном fallback.
- Не проверять Windows API вызовы в unit-тестах; их поведение подтверждается
  ручным smoke и существующими логами `layout_*`.

## Out of Scope

- Установка, удаление или изменение раскладок Windows.
- Изменение пользовательских сочетаний Ctrl, P или CP.
- Изменение правил выбора русской раскладки.
- Выбор раскладки по региону, культуре или раскладке клавиатуры вместо
  установленного HKL.
- Исправление задержек layout switching и изменение Outlook transport.

## Further Notes

Требование относится к низкоуровневому Windows layout resolver-у и должно
оставаться независимым от классификаторов приложений и adapter policy.
