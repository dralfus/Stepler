# Известные ограничения Stepler

Актуально для alpha 0.1.1.

## Открытые ограничения

- PowerShell должен работать через PSReadLine adapter. Для новых сессий adapter загружается из профиля PowerShell; уже открытые окна нужно перезапустить или загрузить adapter вручную. Умный режим строки назначен на `Ctrl+Pause`.
- Windows Terminal с удаленной SSH-сессией не имеет безопасного локального API для редактирования строки на удаленной машине. По умолчанию Stepler подавляет `Pause`/`Ctrl+Pause` в SSH, чтобы не отправлять `^C` и не закрывать сессию.
- Browser/Electron-поля поддерживаются только через безопасные app policies и проверяемые методы. Generic `ClipboardSelection` и `SendInput` fallback-и остаются рискованными и выключены, если не включить их явно через диагностику.
- `UIAutomationDocumentText` надежен для явно выделенного текста и отдельных web/document-поверхностей, но не является универсальным способом понять слово слева от caret во всех приложениях.
- Telegram Desktop поддерживается отдельной policy для Qt-окна Telegram. Если изменится process name или класс окна, потребуется обновить диагностику и policy.
- Word adapter зависит от установленного Microsoft Word и доступности COM.
- Linux support отложен.

## Закрыто в текущей ветке

- PowerShell/Windows Terminal больше не использует `Ctrl+C` как универсальное копирование текущей строки.
- В SSH-сессиях `Pause`/`Ctrl+Pause` больше не отправляют `^C`.
- Telegram больше не распознается как SSH только из-за символа `@` в заголовке чата.
- PSReadLine profile installer больше не привязан к одному пути Documents и учитывает локальный `%USERPROFILE%\Documents`.
- Локальные пути конкретной машины удалены из рабочего кода и пользовательской документации.

## Блокирующие data-loss баги

На текущий момент неизвестны. Если adapter не может подтвердить контекст или `expected_before_text`, он должен отказаться от замены.
