Stepler known issues / release notes for alpha 0.1.0

Known limitations:

- Browser/Electron/Codex-style controls are not a primary supported path yet. Generic ClipboardSelection and SendInput fallbacks are risky and disabled unless explicitly enabled.
- PowerShell should use the PSReadLine adapter. The smart-line shortcut is Ctrl+Pause.
- Browser/Electron/Confluence/Codex generic editing surfaces use only the strict UIAutomationEditableText method. If Windows UI Automation does not expose a focused writable Edit element with reliable text/caret patterns, Stepler refuses to mutate them.
- UIAutomationDocumentText is selection-only in alpha: it can replace explicitly selected text in UIA TextPattern document surfaces, but it does not infer the word/line around a collapsed caret. Selected text uses a fast foreground-checked apply path by default; set STEPLER_UIA_DOCUMENT_STRICT_APPLY=1 to use the slower UIA preflight/verify path for diagnostics.
- The installer is framework-dependent and requires .NET 9 Desktop Runtime on the target machine.
- Linux support is postponed.
- Word support depends on installed Microsoft Word and COM availability.

No currently known blocking data-loss bugs after the latest Notepad, PowerShell, Word, UIA fixture, clipboard, and tray fixes.
